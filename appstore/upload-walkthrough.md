# Archive & Upload Walkthrough

End-to-end. Most steps are once-only.

---

## One-time prep

### 1. `Info.plist` — export compliance flag

Add this to `Spool/Info.plist` so the upload never prompts you about
encryption:

```xml
<key>ITSAppUsesNonExemptEncryption</key>
<false/>
```

If the file is generated by xcodegen, add the equivalent in `project.yml`
under the Spool target's `info.properties`:

```yaml
info:
  properties:
    ITSAppUsesNonExemptEncryption: false
```

Then `xcodegen generate`.

### 2. Version + build number

In `project.yml` (or directly in Info.plist):
- `CFBundleShortVersionString` = `1.0.0` (the version users see)
- `CFBundleVersion` = `1` (the build number, monotonic; bump every upload)

Apple's submission requires these to be set on every archive. You can
update mid-review if needed.

### 3. App ID + Capabilities at developer.apple.com

Make sure your `news.getspool.app` App ID has these capabilities enabled
(matching what's in `project.yml`):

- Background Modes (Audio, AirPlay, Picture in Picture — for SpoolPlayer)
- Background Modes (Background processing / refresh — for MentionsNotifier)
- App Groups (only if your widget shares a UserDefaults suite — check
  `SpoolWidget/Info.plist` for `group.news.getspool.app`)
- Push Notifications (if Mentions ever uses remote push instead of local)

### 4. App Store Connect — create the record

[appstoreconnect.apple.com](https://appstoreconnect.apple.com) → My Apps → ➕

- Platform: iOS
- Name: Spool
- Primary Language: English (U.S.)
- Bundle ID: news.getspool.app
- SKU: spool-ios (or whatever you want)
- User Access: Full Access

That creates the "shell" the upload binds to. You don't have to fill in
the description / screenshots yet — the build can land in TestFlight
before metadata is finalized.

## Per-build upload

### 5. Build & archive in Xcode

1. Open `Spool.xcodeproj`.
2. Select the Spool scheme (top bar, next to the device picker).
3. Set the destination to **Any iOS Device (arm64)** — *not* a simulator.
4. **Product → Scheme → Edit Scheme** → Archive → Build Configuration =
   **Release** (it should already be).
5. **Product → Archive**. Takes 2–5 minutes.
6. The Organizer window opens automatically when done. The new archive
   is at the top.

### 6. Distribute

In the Organizer:
1. Select the archive → **Distribute App**.
2. **App Store Connect** → **Next**.
3. **Upload** (not Export) → **Next**.
4. Signing: **Automatically manage signing** → **Next**.
5. Review the summary → **Upload**.

Upload takes 1–3 min. Then Apple processes the binary server-side for
10–30 min. You'll get an email when it's available in TestFlight.

### 7. (Optional) TestFlight first

Once the build appears in App Store Connect → TestFlight:
1. Add yourself as an internal tester.
2. Install via the TestFlight app on your device.
3. Smoke-test: sign in, queue a story, play it, scrub, run a summary,
   open a widget, share to the share extension.
4. Hit the obvious edge cases: Apple Intelligence off, no network, all-
   read filter, dark mode, accessibility-XXX-large Dynamic Type.

External testers (up to 10,000) need a one-time **Beta App Review**
(~24h). Internal testers (your team) don't.

### 8. Submit for App Store review

App Store Connect → My Apps → Spool → iOS App tab:

1. **App Information**
   - Category: News (primary), Productivity (secondary)
   - Content Rights: Doesn't contain third-party content (you're not
     redistributing HN's content — you're a client of their API).

2. **Pricing and Availability**
   - Price: Free
   - Availability: All countries (or whatever)

3. **App Privacy**
   - Click Get Started → Does your app collect data? → **No**.

4. **iOS App** — fill in the version-specific fields:
   - **Description**: paste from `appstore/metadata.md`.
   - **Keywords**: paste from `appstore/metadata.md`.
   - **Promotional Text**: paste from `appstore/metadata.md`.
   - **Support URL**: `https://github.com/ctaloi/spool/issues`
   - **Marketing URL**: `https://getspool.news`
   - **Screenshots**: drag the 5 PNGs from `appstore/screenshots/iphone-6.9/` (in order). Add iPad shots when you have them.
   - **Build**: pick the build that just processed.
   - **App Review Information**:
     - Sign-in info: leave blank (note in App Review Notes that sign-in
       is optional and a test account isn't required).
     - **Notes**: paste from `appstore/review-notes.md`.
   - **Version Release**: "Automatically release this version" (or
     manual if you want to time the launch).

5. Click **Add for Review** → **Submit for Review** at the top.

Apple's typical review time is 24–48 hours. First submissions sometimes
take longer.

## If it gets rejected

The most common reasons for an HN reader:
- **Guideline 5.2.5** (Apps and Extensions for Apple's platforms) — they
  may ask about HN affiliation. Response: the review notes already
  cover this. If they push, point to nominative fair use and the
  privacy policy's "not affiliated" line.
- **Guideline 2.1** (App completeness) — make sure every visible button
  on the first screen does something. If a feature requires Apple
  Intelligence and the reviewer's device doesn't have it on, that can
  read as broken.
- **Guideline 4.0** (Design) — rare for SwiftUI-native apps; usually
  cosmetic feedback you can address with one resubmission.

Resubmission is fast: address the feedback, archive again, bump
`CFBundleVersion`, upload. Same Review queue, same 24-48h.
